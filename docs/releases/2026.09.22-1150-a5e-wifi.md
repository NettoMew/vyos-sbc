# A5E AIC8800 驱动候选镜像 — 2026.09.22-1150-a5e-wifi

仅 Radxa Cubie A5E，默认 `.img.xz`。STA/AP 网络配置继续由 VyOS 管理，本次不创建网络。

## 文件

- `vyos-2026.09.22-1150-a5e-wifi-radxa-cubie-a5e.img.xz`：4 GiB SD 整盘镜像，包含新 SPL/U-Boot。
- 同名 `.iso`：板级系统升级介质，**不更新 SD/SPI 中的固件**。
- `u-boot-2026.09.22-1150-a5e-wifi-radxa-cubie-a5e.bin`：0077 固件，需按介质分别备份、写入、读回校验。
- `SHA256SUMS-2026.09.22-1150-a5e-wifi.txt`、构建配置、源码快照及 provenance 随附。

不要把同一整盘镜像直接复制到 SD 和 NVMe 同时使用，重复 UUID 会破坏介质选择。
NVMe 安装沿用仓库 `scripts/install-a5e-nvme.sh` 的型号/序列号确认流程；现有板上
NVMe 未清盘，仅安装了本次无线资产。已经验证的 0545 旧镜像保留作回退。

## 实现与来源

- 配对内核 178/179 与 U-Boot 0076/0077：SDIO 40 MHz、4-bit、PL7 电源、PM1 复位、
  PM0 host-wake、BLDO1 1.8 V 常供电。保持固件 DT 交接，不改变以太网 MAC 策略。
- Radxa AIC8800 源码固定 `516e3b087763d80c44f5e3b6d2dd63e0d925c91d`，共享 SDIO
  兼容补丁，D80 固件；模块去调试段后签名，保留 `MODULE_SIG_FORCE`。
- `custregd` 默认关闭，遵守 cfg80211 监管规则；不设国家、不解除信道限制。
- 复用 0545 的 `6.18.50-vyos` Image/initrd 和用户空间；新编外置模块、内核 DTB、
  U-Boot，重新生成系统 squashfs、IMG.XZ、ISO。不是重新编译整套内核/用户空间。

## 验证范围

已通过：源码回归、配对 DT 合约、IMG 分区/引导区检查、XZ 测试及完整 4 GiB 解压
SHA256、ISO 全文件校验；SD 正常启动下的强制签名加载、SDIO/固件/接口创建、
AP↔managed 类型切换、三轮被动扫描、重启重复枚举。没有发现 AIC 超时或 Oops。

SD 与 SPI 固件均已更新且完整读回一致，NVMe 驱动资产已部署。新固件的无 SD
SPI→NVMe 冷启动及软件重启也通过了签名、固件、接口、模式切换和扫描验证；两次
各扫描到 5/6/7 个 BSS，介质 UUID、持久层、模块/固件哈希均核对一致，未发现 AIC
超时或 Oops。重启串口明确记录从 sunxi SPI 到 NVMe EFI 的自动启动链。
